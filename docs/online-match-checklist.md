# オンライン対戦チェックリスト

この文書は、フレンド対戦を実ユーザーが遊べる状態まで固めるための確認表です。
CPU対戦や見た目の微調整ではなく、オンライン対戦の同期、復帰、エラー耐性を重点的に確認します。

## 前提

- 対象ルート:
  - `/friend`
  - `/friend/create`
  - `/friend/join`
  - `/friend/room/[roomId]`
  - `/friend/play/[roomCode]`
- 本番の対戦状態はサーバーAPIと共有ストアを正とする。
- Ablyは待機室更新の高速化に使うが、ポーリング復帰が必須の保険になる。
- 参加者の識別はFirebase Authの`uid`を優先し、古いuidなしルームだけニックネームで後方互換する。
- 1回の確認では、同じブラウザの通常タブ、シークレットタブ、別ブラウザ、または別端末を組み合わせる。

## 優先確認シナリオ

### 1. 最小完走

- 2人
- 15秒
- きゅうり上限5本
- classic
- 目的: 作成、入室、開始、1ゲーム終了まで止まらないか確認する。

### 2. 実運用寄り

- 3人
- 15秒
- きゅうり上限5本
- classic
- 目的: 実際のテストプレイに近い人数でShowDownと次ラウンド移行を確認する。

### 3. 最大負荷寄り

- 6人
- 10秒
- きゅうり上限4本
- classic
- 目的: 席配置、同期頻度、タイマー、手札表示の崩れを確認する。

### 4. 復帰テスト

- 3人
- 対局中にホスト、ゲストをそれぞれリロード
- 目的: 読み込み中で止まらず、正しい席と手札に戻れるか確認する。

### 5. 異常操作テスト

- 同名ニックネーム
- 日本語ニックネーム
- 二重クリック
- 手番外クリック
- 目的: サーバー権限とUIガードが一致しているか確認する。

## 現時点の重点監視項目

- ホスト開始直後に「ゲームを読み込み中...」で止まらないか。
- ShowDown後にプレイヤー間で最後のカード表示がズレないか。
- 次ラウンド開始時に前の場札が残らないか。
- Firebase `uid`ベースの席復帰が効いているか。
- Ablyなしでも待機室から対局画面へ遷移できるか。
